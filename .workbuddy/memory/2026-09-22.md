# 2026-09-22

## DT7 + DR16 一控二（两块 C 板各自一个电机）

- 需求：一套 DT7/DR16 同时控制两台电机，每台由一块独立的 RoboMaster C 板驱动。
- 结论：**可行，且两块板之间不需要任何通信**。
- 依据：DR16 的 DBUS 输出是**单工单向**（只发不收），一路 TX 挂多路 RX 不存在总线竞争；USART RX 是高阻输入，一路信号驱动 2~3 个接收端没问题。
- 推荐方案（硬件并联）：
  - DR16 的 DBUS 信号线并联到两块板的串口 RX；两块板 **GND 必须共**；5V **只由其中一块板**给 DR16 供电，另一块只接信号+地。
  - 每块板各自跑自己的 SBUS 解析，取各自通道：板 A 取 ch1（右摇杆垂直）→ 电机1；板 B 取 ch3（左摇杆垂直）→ 电机2。
  - 安全做法：用 s0/s1 拨轮做使能档，避免误碰导致两台同时动作。
- SBUS/DBUS 串口参数：**100000 bps、8 数据位、偶校验、2 停止位、接收电平反相**。接 C 板自带 DR16 接口时反相已由板载电路处理；自行飞线到普通 USART 时需在软件里开 `RxPinLevelInvert`（UART_ADVFEATURE_RXINV）或外加三极管反相。
- 备选方案：一块板收 SBUS 后通过 CAN 转发给另一块（两块板本来就有 CAN），可传更丰富的自定义数据，但要写 CAN 应用层协议。
- 提醒用户：若两台电机能挂同一条 CAN 总线，一块板就够控制两台，不必拆成两块板。

## 追问：两块板距离远、DBUS 物理并联不便 → 改用无线串口

- 用户反馈两块 C 板物理上难以用一根线连起来。**无线串口方案完全可行，而且更适合远距离**。
- 架构：**DR16 只接 C板 A** → 板 A 解析 SBUS → 取出 ch1 自用、把 ch3 打包 → 通过无线串口发给板 B → 板 B USART RX 收包设目标转速。
- ⚠️ 关键坑：**不能把 DR16 的 DBUS 直接接到无线串口模块上透传**。DBUS 是 100 kbps + 偶校验 + 2 停止位 + 电平反相，绝大多数无线透传模块只支持普通 8N1，会全解不出来。必须先解析成普通数据再转发。
- 选型参考：ESP32-C3/C6 + ESP-NOW（延迟 3~10 ms，最低）；nRF24L01+ 串口转接成品模块；HC-12 433 MHz（UART 直连最省事，约 10~30 ms，**半双工**，需 AT 设波特率）；蓝牙 SPP（用户已有经验）；LoRa E32 速率低不推荐。要成对购买，同信道/地址绑定。
- 必须加**超时保护**：板 B 侧 200 ms 未收到新帧就把目标转速归零，防止丢链路后电机保持上一次指令继续转。
- 发送速率 20~50 Hz 足够（DR16 本身约 70 Hz），别发太快。
- 另一个思路：买两个 DR16 分别对频同一个 DT7。DJT DT7 官方未说明支持一发多收，对频通常会覆盖上次绑定，大概率不成立，不作为推荐路径。

## 用户已有硬件：HC-05 蓝牙串口（用于 PC ↔ 板子的调试链路）

- 板间链路可采用 HC-05 一主一从方案；但 PC↔板 A 已占用一对，板 A↔板 B 需**再加一对**，并占用板 A、板 B 各一路额外 USART。
- 前提：必须是真 HC-05（带 KEY 引脚/板载按键，可主从切换）。若模块只有 VCC/GND/TXD/RXD 四针，多为 HC-06/从机克隆，**无法当主机**，需换货。
- 只能在两端的预留串口里挑：本工程 ioc 里仅 USART1(PA9/PB7) 被占用，USART2/3、UART4/5、USART6 均空闲（若用 RoboMaster C 板需另按其原理图核对）。
- 已知坑：SPP 延迟 10~30 ms 且偶发抖动 → 板 B 侧超时保护阈值别设太小，推荐 200 ms（50 ms 会被偶发抖动误停机）。

## 最终目标架构（用户明确）

- 板 A：接 DR16 → 解析 SBUS → 本地完成 **Yaw 速度闭环**（GM6020）→ 把"水平相关"的目标值经蓝牙串口发给板 B。
- 板 B：收帧 → 本地完成 **水平闭环** → 控第二个电机。
- 关键设计原则（已向用户强调）：**谁的电机谁闭环，跨板只传「目标值 / 使能 / 模式」**，绝不把原始 IMU / 编码器反馈跨板传过去当另一块板的闭环反馈——否则 20~40 ms 的蓝牙延迟 + 抖动会直接进入反馈回路，把环路搞振且极难调。
- 若必须让板 B 用板 A 的 IMU 数据，那 IMU 反馈只能进**外环**（慢环，时间常数几百 ms），执行侧的内环（速度/电流环）必须用板 B 本地反馈。
- 分步验证建议：先用两个 USB-TTL + 两串口助手验证 HC-05 透传 → 板 A 先把转发内容打印出来自查 → 板 B 先只收不动电机 → 最后才闭环。

## 需求收敛（用户最终澄清）

- **没有跨板反馈**：两块板各自本地闭环自己的电机（GM6020 编码器反馈就在各自板上），不存在"板 B 用板 A 的 IMU"这种需求。
- 因此跨板只需传 **一个目标转速 + 一个使能位**；蓝牙延迟/抖动完全不进反馈回路，对环路稳定性零影响 → **HC-05 方案完全够用，不需要 CAN，也不需要 ESP-NOW**。
- 帧格式建议 `$B,<rpm>,<en>\r\n`，20~30 Hz（不要跟着 DR16 的 ~70 Hz 每帧都发）。
- 唯一要写扎实的是安全三件套：上电默认目标 0、200 ms 超时归零、板 A 把"遥控器在线"作为使能位下发。
- 建议用 DR16 的 s1/s2 之一做两台同时急停。

## 完整功能需求（最终确认）

- **必须用无线的原因**：两块板中间隔着旋转结构（Yaw 在转台上），有线绕不过去 → 蓝牙（无线串口）是唯一解，CAN 那条路排除。
- 控制分配：
  - **板 A（Yaw，DR16 所在板）用右侧**：右三段开关其中两档 = Yaw 两档固定转速；另一档 = 右摇杆垂直通道给任意转速。
  - **板 B（第二电机/导轨，蓝牙从机）用左侧**：左三段开关切换"两个波形"（往复剖面）；另一档 = 左摇杆左右点动，推到极限可切定速。
- 数据链路：板 A 把**左侧开关 + 左摇杆**打包从蓝牙转发给板 B；板 B 自己跑状态机。
- 建议板 A 只做"搬运"，转发**归一化后的原始量**（sw 档位 + 摇杆 -1000~1000），模式解释放在板 B —— 好处是板 B 可脱离遥控器，用 PC 串口助手直接灌帧调试。
- 三个必做的工程细节：摇杆**中位死区**（±50~80，否则中位会飘）、切换瞬间**目标值斜率限幅**（防档位切换时电机猛冲，尤其导轨这类直线机构）、旋转带来的**蓝牙盲区**要先实测丢帧率再定超时策略（建议两级：短断保持 + 长断停机）。

## 进一步澄清：板 B 控的是导轨滑块，必须行程限位

- 手动档行为更正：**摇杆小幅推 = 按比例给转速左右移动**（不是推到底切定速），且**必须有行程/角度限位不能让它一直走**。
- 位置反馈现成：`Motor.c` 里已有 `current_angle`（`total_rounds` 过零展开 + `offset_ecd` + `gear_ratio`），可直接当"连续位置"用，无需重写编码器解算。
- ⚠️ **最大陷阱**：`offset_ecd` 是上电时记录的，`current_angle=0` 只代表**上电那一刻的位置**，不是行程零点。多圈靠累计、**掉电即失** → 每次上电必须先回零，否则软限位形同虚设。
- 三层限位防御（缺一不可）：① 减速带（接近端点目标转速线性衰减，不硬夹断，防惯性冲过）；② 硬停线（越过后只允许反向逃离）；③ 物理限位开关或堵转电流兜底。
- 回零方法：低速朝一端走，直到限位开关触发 或 堵转判定（转速≈0 且 |given_current| 超阈值持续 ~300 ms）→ 建零。`given_current` 已在 DMA 里，不用额外读。
- 再次印证核心原则：**限位与安全必须放在板 B 本地**，不能由板 A 隔蓝牙算完再发——30 ms 延迟够滑块撞上去了。

## 用户选定的回零方式：手动回中（人以双 versions 双 sladoledanje）

- 用户方案：**上电前先把滑块手动推到行程中间**，之后所有角度限位都以这个中位为 `current_angle = 0` 的原点 → 软限位取对称的 ±值。属于"手动回零"，省掉自动回零状态机。
- 必须配套的三件事：
  1. 导轨上做**物理中点标记**（贴纸/刻线），别每次靠肉眼估；中位偏差会直接吃掉一侧行程。
  2. 软限位取**实测半行程减去余量**（建议留 10~15%），不要顶着真端点设。
  3. 因为**软件无法判断这次上电有没有真的回中**（忘推中间就开机，坐标系全是错的），第三层物理兜底从"建议"升级为**必做**：两侧限位开关，或至少堵转电流检测。
- 标定方法：中位上电 → 用卷尺量总行程 L → 半行程 L/2 → 按 度/毫米 换算 → `RAIL_MAX = +0.85×(L/2)`, `RAIL_MIN = -0.85×(L/2)`。

## CubeMX 里配置 DR16（DBUS）接收的参数

- 本工程 USART1(PA9/PB7) 已被蓝牙占用 → DR16 需另开一路（USART2/3/6、UART4/5，ioc 显示其余全空闲）。
- 参数（STM32F407 + HAL）：
  - Baud Rate **100000**（下拉里没有，直接手输）
  - Word Length **9 Bits（含校验位）** —— 关键坑：HAL 里一旦开校验，字长要含校验位；选 8 实际变成 7 数据位，SBUS/DBUS 解不出来
  - Parity **Even**，Stop Bits **2**（收不到可试 1）
  - Mode **Asynchronous**，OverSampling 16
- DMA：USARTx_RX 加一路，Mode **Circular**，Data Width Byte，Memory 地址自增打开
- NVIC：开 USARTx global interrupt（空闲中断要用）
- GPIO：RX 引脚设 **Pull-up**；生成前看一眼 CubeMX 显示的波特率误差，应 < 0.5%
- 电平反相：接板载 DR16 专用接口时硬件已反相，不用管；飞线到普通 USART 必须软件开 RxPinLevelInvert（CubeMX 不一定有选项，需手写两行）
- 验证判据：稳定收到 18 字节、帧头 0x0F、帧尾 0x00 → 配置正确；收不到先怀疑字长和反相这两项。

## 关键事实：遥控控 Yaw 在工程里已经全部实现（2026-09-23 复查）

- 已存在的模块：`application/remote_control.c/.h`（18 字节 DBUS 解析 + `RC_is_offline()`）、`application/bsp_rc.c/.h`（`RC_Init` DMA 双缓冲 + 空闲中断）、`USART3_IRQHandler` 定义在 remote_control.c（CubeMX 侧刻意不勾 USART3 中断，避免重复定义）。
- 硬件配置：`USART3 / PC11 RX`，波特率 100000，Parity Even，**WordLength 8B + StopBits 1**（与标准步兵代码一致，先前建议的"9 Bits"以实测为准，不必改）；DMA1_Stream1，PC10 为 TX。
- main.c 里已调用 `MX_USART3_UART_Init()` + `remote_control_init()`；主循环 `yaw_rpm_cmd = yaw_target_rpm()`。
- `yaw_target_rpm()` 逻辑：右拨杆 s[1] 上档=YAW_SPEED_1(60)、中档=YAW_SPEED_2(150)、下档=右摇杆 ch[1]（灵敏度 300，死区 60）；**上电需拨杆变化一次才解锁**（防上电即转）；遥控离线 100 ms 后回落到蓝牙 `bt_target_rpm`。
- ⚠️ 代码里**没有任何反相处理**（grep 无 RXINV/AdvancedInit）→ 若板载 DBUS 接口没有硬件反相电路，必须加软件 `RxPinLevelInvert`，否则收到全 0xFF/乱码。
- 待用户确认：DR16 是否已接 PC11、DT7 与 DR16 是否已对频、板子 DBUS 口是否有反相电路。

## 调试记录 2026-09-23：遥控无反应，DMA1_Stream1->NDTR 恒为 36

- 现象含义：NDTR 不递减 = **一个字节都没进 USART3**。注意**反相不会造成这个现象**（反相只是解出乱码，字节照样搬、NDTR 照样变），所以问题在"物理层 / 外设没跑"，不在协议层。
- 三步寄存器定位法：① `USART3->CR1` 的 UE(bit13) / RE(bit2) 是否为 1 → 否则固件没初始化（多半是没重新编译下载）；② `DMA1_Stream1->CR` 的 EN(bit0) 是否为 1 → 否则 DMA 被 transfer error 由硬件关掉，去看 `DMA1->LISR/HISR` 的 TEIF/FEIF；③ 两者都为 1 而 NDTR 仍不变 → 线上真没数据，查接线 / 供电 / DR16 是否真的在发。
- 最快物理层验证：把 USART1 的 TX(PA9) 临时飞线到 PC11，用蓝牙发一个字符，看 NDTR 是否减少 → 变了就说明 MCU 侧配置全对，问题在 DR16 那一侧。
- 其余排查点：DBUS 线是否接到 PC11 而不是 PC10(TX)；5V/GND 是否到位；DR16 对频后指示灯是否常亮；板载 DBUS 口的 5V 是否有跳线/开关控制。
