## 速度环振荡调试（SerialPlot 波形）

- 波形：目标 150rpm，实际转速在 100~420 之间逐采样大幅摆动 → 速度环高频极限环（电机应有啸叫/抖动）。
- 根因分析：GM6020 电压模式(0x2FF) + YAW_SPEED_KP=60 + 1kHz 控制周期 + 1~2ms CAN 反馈延迟，环路增益处于临界，小扰动被来回放大。
- 发现的坑：`YAW_SPEED_MAX_IOUT = 0.0f`，`LimitMax(Iout, 0)` 会把积分项永远清零——直接给 Ki 赋值是无效的，必须同步把 max_iout 设成非 0（建议 2000）。
- 给出的调参路径：Kp 60→15 起步，仍振则减半；平稳有静差后开 Ki=0.5（配 max_iout=2000）；Kd 保持 0。
- 波形均值 ~250 明显高于目标 150，可能是 >50Hz 振荡被 100Hz 采样混叠的假象，不能按均值判断静差方向。
- 待确认：降 Kp 后若带不动负载/静差大，考虑换电流模式(0x1FFE)或检查机械卡滞。

## 稳态差 20rpm 上不去（后续）

- 现象：Kp=75 / Ki=8 / MAX_IOUT=10000 时，转速稳在 ~130，差目标 20，从不超调。
- 根因（重要概念）：GM6020 走**电压模式(0x1FF)**，维持转速全靠抵消反电动势，需要的电压 ≈ (rpm/320)×25000 ≈ 78×rpm。150rpm 就要 ~11700 的电压量；P 项在误差 20 时只给 75×20=1500，剩下的全靠积分补，而 MAX_IOUT=10000 把积分卡死 → 永远差最后那一点。
- 修法：MAX_IOUT 10000 → 20000（已改）。
- 另加可选速度前馈 `YAW_SPEED_FF`（Motor.h，默认 0 = 关闭，改 60.0f 启用），Motor.c 的 spin 分支里叠加后重新限幅。前馈直接给掉反电动势那部分电压，PID 只管摩擦/扰动。
- 后续参数倾向：Ki=8 偏猛（积分时间常数 τ ≈ Kp/Ki ≈ 9ms），Kp=75 偏高（Kp=60 时曾振荡），稳定后可考虑 Kp 40 / Ki 1~2。

## SerialPlot 发指令无反应

- 原因：只接了单向线（USB-TTL RXD ← PA9，只能看波形），**TXD 没接到 PB7(USART1_RX)**，PC 发出的字节物理上进不了 MCU。
- 完整接法：PA9→RXD（上传波形）、TXD→PB7（下发指令）、GND 共地。蓝牙模块若还插着，它的 TX 也在驱动 PB7，调试期应拔掉或断开该线。
- 指令必须以 \r 或 \n 结尾，main.c 的行缓冲靠行尾符判定一行结束；SerialPlot 里要显式写 "50\r" 或勾选追加换行。
- 判据：main.c 的 RX 回调有逐字节回显——发完指令后数据窗口若出现额外字符说明链路已通，完全没动静就是线没接。
- 补充（用户反馈线其实都接了，上述单向接线假设不成立）：真正嫌疑改为 ①PB7 上蓝牙 TX 与 USB-TTL TXD 双驱动冲突 ②SerialPlot 命令框里手写的 `\r` 被当字面字符发出，行内容含非数字 → 整行丢弃 ③COM4 若是蓝牙 SPP 口而非 USB-TTL 口，波特率/配对不匹配。
- 已加诊断代码（main.c）：`g_dbg_rx_bytes` / `g_dbg_cmd_ok` / `g_dbg_cmd_bad` / `g_dbg_cmd_val` 四个 volatile 计数器（Watch 看，不占串口带宽）；`BT_CMD_ECHO=1` 时解析后回显 `OK:50\r\n` 或 `ERR\r\n`；原逐字节回显已删除（会污染 ASCII 波形）。调通后把 BT_CMD_ECHO 改 0。
- **结论性发现（用户确认）：用别的串口助手发同样指令完全正常 → MCU 侧（接线/PB7/波特率/解析）全无问题，故障 100% 在 SerialPlot 的 Send 面板。**
- SerialPlot 根因：命令有 HEX / ASCII 两种格式（官方文档 "Commands can be defined in HEX or ASCII format"）。若格式为 HEX 则 "50" 被当 0x50(=字符'P') 发出；若 ASCII 模式下手写 `\r` 不被转义则发出 `5 0 \ r` 四字节——两种情况 MCU 都判为非数字整行丢弃。
- 最稳写法：SerialPlot 命令用 **HEX 模式填 `35 30 0D 0A`**（'5'=0x35 '0'=0x30 CR=0x0D LF=0x0A），绕开一切转义/格式歧义。
- 另加 `AUTO_STEP_TEST`（main.c，默认 0）：改成 1 后 MCU 自己按 `{0,100,150,0}` 每 3s 循环切目标转速，上电即可看阶跃响应，彻底不依赖上位机下发；收到任意串口指令后自动让位回手动。
- **以上全部诊断代码已按用户要求完整撤销**（main.c 恢复原状：RX 回调恢复逐字节回显 `HAL_UART_Transmit(&huart1, &rx_byte, 1, 10);`，删除 4 个计数器、BT_CMD_ECHO、bt_send_str/bt_send_line、AUTO_STEP_TEST）。已 grep 确认无残留。

## GM6020 转速上限（咨询结论）

- 电压模式下可用转矩 ∝ (V供电 − 反电动势)，反电动势 ∝ 转速；320rpm 空载极限处转矩归零。剩余转矩能力 ≈ (1 − rpm/320)。
- 建议上限：**连续带载 150~180 rpm**（裕量 44~53%）；轻载短时 200~220；≥250 不可用（裕量仅 22%，易掉速+发热）。当前目标 150 处于安全区。
- 实测方法：依次发 100/150/180/200 各停 5 秒，记录 given_current 与 temperature；电流陡增或转速跟不上即到负载极限，回退 20~30rpm。温度 10 分钟内 >60℃ 降额，>70℃ 停机。
- 要更高转速：优先加同步带/齿轮增速（电机仍留在舒服区），其次换 M3508；改电流模式**不能**突破电压极限，只限流保护。
- 安全提醒：电压模式无电流环，机械卡死会直接到堵转电流，建议软件里加 given_current 超阈值停机保护（用户未确认，暂未实现）。
- 当前步骤：先**空转稳住 150**，确认环路本身无问题，再带载对比稳态 pid_output 的增量。
